빌드/패키징 완료. **브라우저를 포함한 전체 실행 검증은 미완료입니다.**

## 통과

- Python 3.12.14 / PySide6 6.11.2 / PyInstaller 6.22.2로 Windows x64 ZIP 생성.
- Python 및 Qt WebEngine/Multimedia/FFmpeg 구성 파일 포함 확인.
- _ssl.pyd와 OpenSSL DLL 두 개가 빌드 Python 원본과 해시 일치.
- 충돌하는 외부 ICU DLL이 번들에 없는지 확인.
- 배포 EXE의 HTTPS 검사: OpenSSL 3.5.8, 인증서 검증 활성화, 공개 버전 API 응답 200,
  ok=true, frozen=true, 종료 코드 0.
- 한글/공백을 포함한 다른 경로에 최종 ZIP을 풀고 Python/Qt 환경 변수를 정리해 실행.
- 일반/호환 모드 모두 실제 MainWindow 생성, 세 가지 탭, 모의 상품/잔액 표시,
  로그아웃 데이터 정리, 합성 H.264/AAC MP4의 유효 영상 프레임 디코딩 및 임시 파일 정리 성공.
- 상점 조회, 세트 조회, 영상 상세/다운로드/미리보기, HTTPS 검사 함수의 AST가 원본과 동일.
- 배포 ZIP SHA-256 일치.

## 미완료: 내장 브라우저

일반/호환 모드 모두 WebEngine 렌더러가 코드 49로 종료되어 HTML/JavaScript 검사를
완료하지 못했습니다. 따라서 normal.json과 software.json의 전체 ok는 false입니다.
다른 세부 검사 항목의 true를 전체 성공으로 해석하면 안 됩니다.

현재 제한된 실행 환경에서 과거에 통과했던 이전 배포본도 같은 코드 49로 실패했습니다.
Chromium의 49는 restricted token 생성 실패를 뜻합니다. 이 비교 결과는 현재 검사 환경의
프로세스 권한 제한이 원인이라는 판단을 뒷받침하지만, 새 배포본의 일반 데스크톱 환경
브라우저 동작을 실제로 검증한 것은 아닙니다.

근거: [Chromium Windows sandbox result codes](https://raw.githubusercontent.com/chromium/chromium/main/sandbox/win/src/sandbox_types.h)

브라우저 보안 격리/인증서 검증을 끄는 우회는 적용하지 않았습니다.
일반 Windows 사용자 환경에서 test-portable.ps1을 실행해 두 모드의 ok=true를 확인해야 합니다.
